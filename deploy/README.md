# Microsoft Foundry Terraform Deployment

Terraform configuration for provisioning a Microsoft Foundry account, project, and Anthropic model deployment in Azure.

## Overview

[main.tf](main.tf) creates the infrastructure used by the repository's [Python agent](../agent/README.md). It targets the active Azure subscription and uses `eastus2` as the region.

| Resource | Configuration |
| --- | --- |
| Random name | One-word `random_pet` with the prefix `test` |
| Resource group | `<random-name>-rg` |
| Foundry account | `<random-name>-rg`; `AIServices` kind, `S0` SKU, project management enabled |
| Foundry project | `<random-name>-project` |
| Model deployment | `<random-name>-deployment`; Anthropic `claude-opus-5-5-fast`, version `2`, `GlobalStandard` SKU, capacity `1` |

The account and project each have a **system-assigned managed identity**. The account enables **public network access** and **local authentication**. The configuration does not create role assignments, private endpoints, or an application runtime.

## Features

- Generates a shared name prefix for the provisioned resources.
- Provisions the Foundry account and project with the AzureRM provider.
- Creates the model deployment with AzAPI using `Microsoft.CognitiveServices/accounts/deployments@2025-10-01-preview`, after the project is created.
- Exposes resource names and the account's Anthropic API base URL as Terraform outputs.

## Requirements

- **Terraform CLI** to run the configuration, which is written in **HCL**. No minimum Terraform version is declared.
- **Azure CLI** for the interactive authentication workflow below.
- An Azure subscription with permission to create the resources and access to the configured model in the selected region. Confirm model availability, quota, and any access or terms requirements before applying; see Microsoft's [Claude deployment guide](https://learn.microsoft.com/en-us/azure/foundry/foundry-models/how-to/use-foundry-models-claude).

Terraform installs these providers during initialization:

| Provider | Purpose | Declaration |
| --- | --- | --- |
| `hashicorp/azurerm` | Azure location/subscription data sources, resource group, Foundry account, and project | Explicit in [providers.tf](providers.tf) |
| `azure/azapi` | Model deployment through the Azure Resource Manager API | Explicit in [providers.tf](providers.tf) |
| `hashicorp/random` | Resource naming through `random_pet` | Implicitly inferred from the resource type |

Provider versions are **not pinned** in the configuration. Retain and commit the `.terraform.lock.hcl` file generated by `terraform init` to make subsequent provider selections reproducible.

## Usage

### 1. Get the configuration

```bash
git clone https://github.com/jaredmmartin/microsoft-foundry-agent.git
cd microsoft-foundry-agent/deploy
```

If the repository is already cloned, change into its `deploy` directory. Run the remaining Terraform commands from there.

### 2. Authenticate to Azure

Sign in, select the target subscription, and export its ID for the providers:

```bash
az login
az account set --subscription "<subscription-id>"
export ARM_SUBSCRIPTION_ID="$(az account show --query id --output tsv)"
```

This workflow uses the signed-in user's Azure CLI credentials; see [Terraform authentication to Azure](https://learn.microsoft.com/en-us/azure/developer/terraform/authenticate/authenticate-to-azure) for other authentication methods.

### 3. Review configuration

There are **no input variables**, `.tfvars` requirements, or `.env` files for this configuration. To customize the deployment, edit [main.tf](main.tf) directly:

| Setting | Current value | HCL location |
| --- | --- | --- |
| Name prefix | `test` | `locals.name_prefix` |
| Region | `eastus2` | `data.azurerm_location.this.location` |
| Account SKU | `S0` | `azurerm_cognitive_account.this.sku_name` |
| Model format / name / version | `Anthropic` / `claude-opus-5-5-fast` / `2` | `azapi_resource.this.body.properties.model` |
| Deployment SKU / capacity | `GlobalStandard` / `1` | `azapi_resource.this.body.sku` |
| Provider country / industry | `US` / `other` | `azapi_resource.this.body.properties.modelProviderData` |
| Provider organization name | Value of `local.name_prefix` | `azapi_resource.this.body.properties.modelProviderData.organizationName` |

The model values above describe the checked-in configuration; confirm that Azure accepts this exact model/version/region combination for your subscription. The deployment sets `schema_validation_enabled = false`, so AzAPI's local schema validation is disabled; Azure still validates the API request.

### 4. Initialize, validate, and deploy

```bash
terraform init
terraform validate
terraform plan
terraform apply
```

Review the proposed changes before confirming `terraform apply`.

No remote backend is configured, so Terraform uses **local state** by default. Keep the state files available for future updates and cleanup. The repository's `.gitignore` excludes `.terraform/` and Terraform state files.

### 5. Read deployment outputs

```bash
terraform output
terraform output -raw cognitive_deployment_name
terraform output -raw cognitive_deployment_url
```

| Output | Value |
| --- | --- |
| `resource_group_name` | Created resource group's name |
| `cognitive_account_name` | Created Foundry account's name |
| `cognitive_deployment_name` | Model deployment's name |
| `cognitive_deployment_url` | `https://<custom-subdomain>.services.ai.azure.com/anthropic` |

The URL is the **Anthropic API base URL**, not a project endpoint. No API keys or tokens are output. Application setup is separate; see the [agent README](../agent/README.md).

### 6. Clean up

To remove the resources managed by this configuration, use the same directory, state, and Azure subscription:

```bash
terraform plan -destroy
terraform destroy
```

Review the deletion plan before confirming destruction.
